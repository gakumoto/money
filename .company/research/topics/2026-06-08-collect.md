### 21. LangChain が「context assembly の 4 戦略」を公式整理
- ソース: https://thomas-wiegold.com/blog/prompt-engineering-best-practices-2026/
- 公開日: 2026年（最新版）
- 要点（3行以内）:
  - AI エージェントの失敗の大半は「プロンプトの悪さ」ではなく **context assembly の失敗**
  - LangChain が 4 戦略に整理: **Write（外部永続）/ Select（RAG取得）/ Compress（要約圧縮）/ Isolate（エージェント別分離）**
  - 「モデルを賢くする」より「何を渡すか」のレイヤーで戦う設計思想
- 投稿アイデア:
  - 型: 朝学び型 / 教育目的
  - 切り口: 「AI エージェントが失敗する原因の大半、モデルの賢さじゃなくて『何を渡してるか』。LangChain が整理した 4 戦略 (Write / Select / Compress / Isolate) は、Claude Code 使ってる人ほど刺さるはず」

### 22. プロンプト長の最適スポットは 150〜300 語、3,000 トークンで性能低下開始
- ソース: https://thomas-wiegold.com/blog/prompt-engineering-best-practices-2026/
- 公開日: 2026年
- 要点（3行以内）:
  - 最適プロンプト長は **150〜300 語**
  - **3,000 トークン超**から推論性能が落ち始める（モデル横断の傾向）
  - 「長く書くほど賢くなる」は誤解。むしろ短い方が安定
- 投稿アイデア:
  - 型: 朝学び型 / 教育目的
  - 切り口: 「プロンプトは 150〜300 語がスイートスポット。3,000 トークン超えると推論精度が落ち始める。『長く詳しく書くほど賢くなる』って思ってる人、損してます」

### 23. Lost in the middle: 長文プロンプトの中央情報は精度 30% 以上低下
- ソース: https://thomas-wiegold.com/blog/prompt-engineering-best-practices-2026/
- 公開日: 2026年
- 要点（3行以内）:
  - 長いプロンプトの中央に置かれた指示は **30% 以上の確率で見落とされる**
  - 「重要な指示は冒頭か末尾」が鉄則
  - Claude Code の CLAUDE.md でも同じ原則が効く
- 投稿アイデア:
  - 型: 夜振り返り型 / 教育目的

### 24. Claude 向け: XML タグで構造化、煽り口調は逆効果
- ソース: https://thomas-wiegold.com/blog/prompt-engineering-best-practices-2026/
- 公開日: 2026年
- 要点（3行以内）:
  - Claude には `<instructions>` `<context>` `<example>` の **XML タグで構造化** が最強
  - `<example>` で囲んだ few-shot 3〜5 例で計測可能な精度向上
  - 「CRITICAL!」「YOU MUST」など大文字強調・煽り口調は **逆効果**。落ち着いた直接的指示が勝つ
- 投稿アイデア:
  - 型: 朝学び型 / 教育目的
  - 切り口: 「Claude に『絶対に〜しろ！』って書くの、今すぐやめた方がいい。逆効果なんです。落ち着いた指示の方が精度上がる。XML タグで囲むのが今の作法」

### 26. LCEL: `prompt | model | StrOutputParser()` パイプ記法が標準
- ソース: https://medium.com/@glenpatzlaff/better-prompt-chaining-using-langchain-expression-language-lcel-d51474b18d73

### 27. 否定形を肯定形に書き換えるだけで精度が上がる
- ソース: https://thomas-wiegold.com/blog/prompt-engineering-best-practices-2026/

  - 型: 教育目的 / ハック共有
  - 切り口: 「『〜するな』って書くより『〜だけする』。プロンプトの否定形は AI の精度を下げます。"mock を使うな" → "実データのみ" に書き換えるだけで結果変わる。1 行ハック」
