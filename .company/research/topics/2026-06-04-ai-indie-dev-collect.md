## 1. Claude Code を「新卒部下」として使い倒すワークフロー

### [Claude Codeで個人開発が3-5倍速くなった実測値]
- ソース: https://zenn.dev/yoshiaki0217/articles/9dd7a3666d475f
- 公開日: 2026-05 (推定 / 直近1か月以内)
- 要点（3行以内）:
  - 新機能開発が「2-3時間 → 30-60分」、バグ修正が「30分-1時間 → 5-15分」
  - 鍵は CLAUDE.md と ai/rules/ 配下の役割分割。**プロンプト工夫より環境設計が勝つ**
  - 失敗パターンを `tasks/lessons.md` に蓄積するループで、同じミスを繰り返さない
- 投稿アイデア:
  - 型: 朝学び型 / 教育目的
  - 切り口:「Claude Codeで開発が3倍速くなったの、コツは1つ。プロンプトじゃなくCLAUDE.mdを2時間かけて書くこと。これだけで新卒部下が能動的に動くエンジニアに変わった」
  - バズ要素: 千円単位の代わりに「3倍 / 2時間」など具体数字、命令型「書け」を末尾に

### [Claude Codeに任せてはいけない3つの領域]
- ソース: 同上
- 要点:
  - 本番デプロイ判断 / セキュリティ実装 / 大規模で曖昧なリファクタは人間
  - 「やらせない領域」を先に定義することで信頼度と品質が同時に上がる逆説
  - 「400行超のPRは分割せよ」を CLAUDE.md に明記すると暴走しない
- 投稿アイデア:
  - 型: 夕失敗型 / 信頼構築
  - 切り口:「Claude Codeに全部任せようとして1回サービス壊しました。本番デプロイ・セキュリティ・大規模リファクタ。この3つだけは絶対に渡さない。線引きしてから速くなった」

## 2. ひとり会社 × AI-CEO Framework

### [一人会社の業務98%を$250/月で自動化するOSS]
- ソース: https://zenn.dev/7788/articles/6c3f54d0efc958
- 公開日: 2026-05 (直近)
- 要点（3行以内）:
  - Claude Code 上に 15 体のAIエージェント (CTO/CFO/CMO/Legal/HR…) を載せて経営チーム自体をコード化
  - メール送信・デプロイ・請求書発行など対外アクションは必ず承認キューを経由 (Human-in-the-Loop)
  - `.company/` ディレクトリに VISION.md / STATE.md / decisions/ を置き「経営のGitOps化」
- 投稿アイデア:
  - 型: 昼進捗型 / 信頼構築
  - 切り口:「ひとり会社をAIに任せたら業務の98%が回り始めた。CTO・CFO・CMOがClaude Codeの中にいる。月$250。社員ゼロで意思決定ログがGitに残る。怖いけど速い」
  - 自社の `.company/` 構成と直接かぶるので、ユーザーの実体験ネタとして展開可能

### [仮想会社の落とし穴=モノリス設計でコンテキストが破綻する]
- ソース: 同上
- 要点:
  - Orchestrator のコンテキスト使用率を 10-15% に抑えるためエージェントを分散
  - 「全部Claude.md 1枚」だと長時間稼働で破綻する
  - 仮説検証ゲートを6フェーズ強制して「誰も欲しがらない物を作らない」
- 投稿アイデア:
  - 型: 夕失敗型 / 教育目的
  - 切り口:「CLAUDE.md 1枚に全部書いたら、Claude Code が途中で迷子になった。原因はコンテキスト肥大。分割して10-15%に抑えたら別物になった。長文1枚は罠」
