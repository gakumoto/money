# ライティング原理集

`.company/reading/` から抽出した「人を動かす文章技術」の中央集約版。
**すべての文章生成 AI スタッフは投稿/記事生成前に本ファイルを読む**。

## 使い方 (AI スタッフ向け)

各原理に **メディアタグ**が付いている。AI スタッフは生成対象に応じてフィルタする:

| タグ | 意味 | 適用スキル |
|------|------|-----------|
| **[両方]** | Threads / note 両方に適用 | threads-create-post / threads-daily-run / note-article-generate すべて |
| **[note]** | note 記事 (長文) 向け | note-article-generate のみ |
| **[Threads]** | Threads 投稿 (短文) 向け | threads-create-post / threads-daily-run のみ |

### 適用フロー

1. 投稿/記事の**目的を決めた後**に本ファイルを読む
2. メディアタグでフィルタする ([両方] + 自分のメディアタグ)
3. **原理を 2〜3 個ピック**して当該投稿に意識的に適用 (note は 3〜5 個まで)
4. 矛盾があれば `.company/CLAUDE.md` の「書いてはいけないこと」「投稿の品質チェックリスト」を優先

## 7 カテゴリ全体図

1. **冒頭フック** — 1 行目で注意を奪う
2. **説得の心理学** — プリ・スエージョン + 6 つの影響力
3. **物語と構造** — 失敗→学びの 5 段階
4. **断定と弱さ開示** — ですます基本、リアル感
5. **読者の動機変容** — 有益性→共感→哲学
6. **数字・固有名詞・体験** — ファクトベース、捏造禁止
7. **CTA と余韻** — 命令型・問いかけ・続編の匂わせ

## 1. 冒頭フック

### 1.1 「特権的瞬間」を冒頭で作る `[両方]`
**核心**: 読者の注意を「あなたのテーマに集中している状態」に持ち込んでから本論に入る。何の前置きもなく結論を出すより、注意を奪う一言を先に置く方が刺さる。
**出典**: PRE-SUASION 第 2 章「特権的瞬間 (モーメント)」
**良い例**: 「給料日前、財布に 327 円しかなかった。」← 数字・状況・感情の 3 点同時
**避けるパターン**: 「今日は副業について書きます」← 注意を奪う要素ゼロ

### 1.2 固有名詞 × 数字 × ターゲットの 3 点セット `[両方]`
**核心**: 1 行目に**固有名詞 1 つ・数字 1 つ・誰宛か明示**の 3 要素を入れる。1 つでも欠けると弱い。
**出典**: 書いて「億売り人」になる 第 5 章、`.company/CLAUDE.md` 投稿の品質チェックリスト
**良い例**: 「ユニクロでバイトしながら note で月 5 万稼ぐ 32 歳ワーママ」
**避けるパターン**: 「大手企業で働きながら副業してる主婦」← 抽象的・数字なし

### 1.3 注意を引く「磁力要素 (マグネタイザー)」を使う `[両方]`
**核心**: 読者の脳が勝手に注目してしまう要素 = 「自分と関係しているもの・未完了のもの・ミステリアスなもの」を冒頭に配置する。
**出典**: PRE-SUASION 第 6 章「磁力要素 (マグネタイザー)」
**良い例**: 「ぼくが Threads で 1 度だけバズった日に、たった 1 つだけ普段と違うことをしていた。」← 未完了 + ミステリー
**避けるパターン**: 「Threads でバズるには 5 つの方法があります」← 完結してて続きを読む理由がない

### 1.4 弱さ枕詞で入る `[両方]`
**核心**: 強気な宣言ではなく、自分の弱さや疑問を冒頭に置くと共感が走る。Threads のような会話プラットフォームで特に強い。
**出典**: `.company/marketing/feedback/gaku_ai_life.md` のバズ要素 (Phase 2 必須 5 要素)
**良い例**: 「ぶっちゃけ、ぼくはまだ 0 円です。」「続くか不安だけど、書いてみる。」
**避けるパターン**: 「結論から言うと、これさえやれば必ず稼げます」← 売り文句で距離が出る

## 2. 説得の心理学

### 2.1 説得の前に「下準備 (プリ・スエージョン)」をかける `[note]`
**核心**: 何かを売る前に、相手の注意を**どこに向けるかを設計**する。先に文脈をセットしてから本題を出す方が、同じ内容でも 2〜3 倍刺さる。長文構造でこそ威力を発揮する原理。
**出典**: PRE-SUASION 序章
**良い例**: 商品紹介の前に「ぼくが 5 ヶ月間、月 0 円だった話」を語る → 読者が「自分も同じ状況」と接続してから本題に入る
**避けるパターン**: いきなり「note 買ってください」と出す → 文脈がないので刺さらない

### 2.2 6 つの影響力の武器を使い分ける `[両方]`
**核心**: 返報性 / 好意 / 権威 / 社会的証明 / 希少性 / 一貫性。1 投稿につき 1〜2 個を意図的に使う。全部盛ると胡散臭くなる。
**出典**: PRE-SUASION 第 10 章 + 影響力の武器
**良い例**: 「権威」→ 「実際に試した結果」「6 ヶ月続けてわかった」/ 「社会的証明」→ 「フォロワーから 100 件こんな声が」
**避けるパターン**: 1 投稿に 5〜6 個全部入れる → 売り込み色が強すぎて警戒される

### 2.3 「失敗の公開」が信頼の最強リテンション `[両方]`
**核心**: 成功談だけ書く運営者は信頼されない。**失敗・苦悩・脆弱性をオープンにすること**が、ユーザーとの距離を劇的に縮める。
**出典**: お金を稼ぎたくて読み始めた人に推される note の書き方 第 5 章
**良い例**: 「先月は売上 0 円でした。何を間違えていたか書きます」← 弱さ開示で距離が縮まる
**避けるパターン**: 「3 ヶ月で月 100 万達成しました!」連発 → 自慢に見えて読者が離れる

### 2.4 感情に火をつけてから論理で納得させる `[note]`
**核心**: 人は合理的理由だけでは買わない。**感情で欲しいと思った後**に、合理的理由を提示して購買を正当化する。順番が逆だと売れない。販売 LP / 有料 note の構造。
**出典**: 書いて「億売り人」になる (感情承認欲求・優越感・自己実現)
**良い例**: 「ワンランク上の自分を見せたい」(感情) → 「だからこの note は今だけ半額」(論理)
**避けるパターン**: 機能・スペックだけ並べる → 感情接続ゼロで購買意欲が湧かない

## 3. 物語と構造

### 3.1 失敗 → 学び の構造を最低 1 箇所必ず作る `[両方]`
**核心**: 全ての記事・投稿に「失敗 → 学び」の構造を**最低 1 つ**入れる。これが無いと「ふーん」で終わる。Threads では 1 投稿で完結、note では章レベルで配置。
**出典**: 書いて「億売り人」になる 第 5 章 + `note-article-generate` の SKILL.md 心得
**良い例**: 「自動投稿が止まってて 3 日損した。原因は API キーの期限切れ。これで気づいた監視の重要性」
**避けるパターン**: 抽象論だけで具体的な失敗エピソードが無い → 読み終わって何も残らない

### 3.2 時系列で謎解き要素を入れる `[note]`
**核心**: 重要な出来事は時系列で語る。「朝起きて発覚 → 原因究明 → 真因発見 → 対策」のように**謎解き構造**を入れると最後まで読まれる。Threads では尺が足りないので note 専用。
**出典**: 書いて「億売り人」になる 第 5 章 (滑り台構造)、`note-article-generate` 心得
**良い例**: 「朝、フォロワーが急増していた。なぜか分からず投稿履歴を遡って、ある 1 投稿に辿り着いた」
**避けるパターン**: 時系列バラバラに学びを並列で書く → 物語性ゼロで読み流される

### 3.3 5 段階構成 (無料記事 1800 字以内の場合) `[note]`
**核心**: 無料 note は**フック → 物語 → 学び 3 つ → ステータス → 余韻**の 5 段階。**学び 5 個は多すぎる、3 個に圧縮**。
**出典**: `note-article-generate` の SKILL.md 字数方針
**良い例**: 1. フック (100 字) / 2. 核心の物語 (700 字) / 3. 学び 3 つ (400 字) / 4. ステータス (300 字) / 5. 余韻 (200 字)
**避けるパターン**: 学び 7 個並べる、フックなしで結論から始める

### 3.4 フィクション化禁止 (体験ベース必須) `[両方]`
**核心**: 数字・固有名詞・実績は元データに無いものを書かない。盛らない・推測で書かない。オーナーが言ってない感情・判断も書かない。
**出典**: `.company/CLAUDE.md` 危険ワード管理、`note-article-generate` の捏造禁止セクション
**良い例**: 「フォロワー X」(ファクトの最新値) / 「投稿 N 本」(`posted/` の実数)
**避けるパターン**: 「3 ヶ月で月 100 万」(ファクトに無い) / 「自動化で時間が 10 倍に」(根拠なし)

## 4. 断定と弱さ開示

### 4.1 曖昧表現を避けて「断定」する `[両方]`
**核心**: 「〜かもしれません」「〜と思います」は信頼されない。ですます調のままでも**明確に断定**する。
**出典**: `.company/CLAUDE.md` 全社ライティングルール
**良い例**: 「やめた方がいいです」「ぼくはまだ 0 円です」← ですます調 + 明確な断定
**避けるパターン**: 「やめた方がいいかもしれません」「0 円かもしれません」← 曖昧で弱い

### 4.2 ですます基本、要所で「だ・である」を混ぜる `[両方]`
**核心**: gaku_ai_life の基本は「ですます調」。だ・である調だけで書くとビジネス書っぽくキャラに合わない。**要所だけ「だ・である」で締める**のが自然。
**出典**: `.company/CLAUDE.md` の「断定」ルール解釈
**良い例**: 「これでぼくの note は 5 ヶ月間、月 0 円でした。続けるしかない。」(ですます→断定で締め)
**避けるパターン**: 「note とは情報資産である。蓄積こそが価値だ。」← 全体が硬すぎてキャラと合わない

### 4.3 装飾絵文字は禁止、思考系のみ文末 1 個まで `[両方]`
**核心**: 装飾系 (🔥✨🙌🌟💪) は**禁止**。思考・表情系 (🤔😅😌😂😭) のみ**文末 1 個まで OK**。note のセールスコピーは絵文字なし。
**出典**: `.company/CLAUDE.md` 絵文字ルール (2026-05-13 改訂)
**良い例**: 「ぶっちゃけ、いくら稼げました?🤔」「0 円です😅」
**避けるパターン**: 「頑張ろう🔥✨」「これは🤔大事だ」(複数個・文中・装飾系すべて NG)

### 4.4 「皆さん」は使わない `[両方]`
**核心**: 「皆さん」「皆様」は距離が出る。**主語なし問いかけ**または「あなた / 君」を使う。
**出典**: `.company/CLAUDE.md` 全社ライティングルール、`.company/marketing/feedback/gaku_ai_life.md`
**良い例**: 「ぶっちゃけ、いくら稼げました?」「なんて言ってますか?」(主語なし問いかけ)
**避けるパターン**: 「皆さん、こんにちは」「皆様にお伝えしたいことが」

## 5. 読者の動機変容

### 5.1 入会動機を「即物的有益性」、継続動機を「共感・哲学」に分ける `[note]`
**核心**: 入り口は「500 円払って 1000 円稼ぐ」で財布を開かせる。継続は「クリエイターの思考プロセス」で繋ぎ止める。**入り口と継続で訴求点を変える**。メンバーシップ・有料 note の設計原理。
**出典**: お金を稼ぎたくて読み始めた人に推される note の書き方 第 2-3 章
**良い例**: 無料 note (有益性で集める) → 月額メンバーシップ (共感・哲学で繋ぐ)
**避けるパターン**: 全コンテンツで「稼ぐハウツー」だけ → ユーザーが飽きる + クリエイターが疲弊

### 5.2 「塾・ジムモデル」の損失回避を作る `[note]`
**核心**: ユーザーが「解約 = 理想の未来を諦めること」と感じる構造を作る。**蓄積 (ストック) が圧倒的な割安感**を生み、休眠ユーザーも繋がる。note の蓄積型課金の核。
**出典**: お金を稼ぎたくて読み始めた人に推される note の書き方 第 3 章 (塾・ジムモデル)
**良い例**: 「note 200 本のアーカイブ。今やめたら全部見れなくなる」← 損失回避を刺激
**避けるパターン**: 「最新記事だけが価値」と訴求する → 蓄積価値が伝わらず解約されやすい

### 5.3 「クローキング (覆い隠し)」で書きたい哲学を有益性に寄せる `[note]`
**核心**: クリエイターが本当に書きたい「哲学・観点」をそのまま出さず、**「有益性の衣服を着せて」発信**する。両者のメンタル健康を保つ高度な生存戦術。長文 note でこそ哲学を仕込める。
**出典**: お金を稼ぎたくて読み始めた人に推される note の書き方 第 4 章
**良い例**: 哲学「フリーランスが自分の魂を守るには」→ 有益性形「note 単価を上げる 3 つの戦術」と書く
**避けるパターン**: 哲学そのまま「自分の魂を売らない生き方について」← 抽象的すぎて読まれない

## 6. 数字・固有名詞・体験

### 6.1 千円単位の生々しい数字を使う `[両方]`
**核心**: 「月 100 万」より「先月は 87,300 円でした」の方がリアル。**端数のある千円単位の数字**が信頼を生む。
**出典**: `.company/marketing/feedback/gaku_ai_life.md` のバズ要素 (Phase 2 必須 5 要素)
**良い例**: 「3 ヶ月で 12,540 円稼いだ」「フォロワー 327 人」「投稿 41 本」
**避けるパターン**: 「月 100 万」「フォロワー 1 万人」← 切りの良い数字は嘘くさく見える

### 6.2 危険ワードを売り文句で連発しない `[両方]`
**核心**: 「月 100 万」「月 7 桁」「収益化」「マネタイズ」「初心者でも稼げる」は**1 投稿 1 個まで・実体験の文脈で**のみ。連発するとアカウント削除リスク。
**出典**: `.company/CLAUDE.md` アカウント削除リスク管理 (Threads7&8 の教訓)
**良い例**: 「先月、初めて 5 万円超えました」(実体験 + 控えめな数字)
**避けるパターン**: 「月 100 万!月 7 桁!誰でも稼げる!」(売り文句として連発 = 情報商材判定)

### 6.3 ファクトベース必須・確認できない数字は書かない `[両方]`
**核心**: `.company/marketing/accounts/<account>.md` の「ファクトベース」セクションに書かれた数字・期間・実績だけを使う。**確認できない数字は書かない**。
**出典**: `note-article-generate` の SKILL.md 「★ 捏造禁止」(2026-05-16 D-020 追加)
**良い例**: ファクトに「Day 23 / フォロワー 327 / posted 41 本」とあれば、その数字を使う
**避けるパターン**: 「Threads 2 ヶ月続けて」(ファクトの Day 数で確認せず勝手に書く)

## 7. CTA と余韻

### 7.1 末尾は断定 or 問いかけで締める `[両方]`
**核心**: 投稿の最後の 1 文は**断定**または**問いかけ**。曖昧に終わると読者は何もせず通り過ぎる。
**出典**: `.company/CLAUDE.md` 投稿の品質チェックリスト
**良い例**: 「ぼくはまだ 0 円です。」(断定で余韻) / 「あなたなら、どう書きますか?」(問いかけ)
**避けるパターン**: 「皆さん、頑張りましょう」「私も精進します」← 行動を促さない締め

### 7.2 続編の匂わせで再訪を作る `[両方]`
**核心**: 無料 note や Threads 投稿の末尾は**「続きを読みたい」状態**で終わる。完結させると次が見られない。
**出典**: お金を稼ぎたくて読み始めた人に推される note の書き方 第 3 章 (未完の期待)、`note-article-generate` 心得
**良い例**: 「明日は、これを失敗した日の話を書きます」(続編予告) / 「続きはまた明日」
**避けるパターン**: 「以上です。ありがとうございました。」← 完全に閉じる = 次がない

### 7.3 売り込み比率は「9 : 1」を死守 `[両方]`
**核心**: **有益 9 : 誘導 1** が黄金比。価値の試食を 9 割提供し、売り込みは 1 割。Threads はアカウント全体の投稿比率、note は無料/有料記事の比率に適用。
**出典**: `.company/CLAUDE.md` アカウント削除リスク管理 (ひで / インスタハカセ / あわを。3 者共通)
**良い例**: 10 投稿のうちリンク付きは 2〜3 本まで。残りは無料の学び・気づき
**避けるパターン**: 10 投稿中 6〜7 本が note 誘導 → 売り込み臭で削除リスク

### 7.4 スパイダーマーケティング: 1 つの記事から複数導線 `[note]`
**核心**: 1 記事は単体で終わらせず、**他の無料/有料コンテンツへの内部リンク**を網目状に張る。少数集客でも一人当たりの成約数を 2〜3 倍にできる。note 内部リンクの設計原理。
**出典**: 【超本質】noteでデカく稼ぐ 第 4 章 (スパイダーマーケティング)
**良い例**: 無料記事の末尾に「詳細は有料 note へ」/ 有料記事の中で「関連の別有料 note も」
**避けるパターン**: どの記事も独立完結 → 1 つ読まれて終わり、循環しない
