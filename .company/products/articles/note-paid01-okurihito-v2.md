# コードを書けないぼくが、AIに"自分専用ツール"を作らせて、Threads自動投稿まで動かした全手順

「AIで副業」が気になる。でも、コードなんて書けない。
——そんな人へ。

ぼくは2年目のSEだけど、最近作ったツールのコードは、ほとんど自分で書いてません。

このリポジトリを「Threads×note でマネタイズするコンテンツ会社」として

1. CLAUDE.md … 会社の方針・社員名簿・発注プロトコル・下書きキューの仕様

## 本題：Threadsに"自動で"投稿させる

問いかけは、これだけでOK。

```
自動投稿をしたい
```

選択肢を出してくれるので、初めてなら「1番」を選択。すると、自分で操作するところを順番に教えてくれます。
（案内が薄いと感じたら「もっと詳しく教えて」と返すと、かなり詳細に出してくれます。）

自動投稿には、**API連携**が必要です。
API＝他のサービスの機能を、決まった頼み方で借りるための窓口。

### ① Metaのトークンを取得する

1. 表示されたURLに飛ぶ
2. 右上の「マイアプリ」をクリック
3. 右上の「アプリを作成」をクリック
4. アプリ名とメールアドレスを決める
5. ユースケースで「**ThreadsAPIにアクセス**」を選択
6. ビジネスは「現時点ではビジネスポートフォリオをリンクしない」を選択
7. 要件はそのまま「次へ」
8. 最後に「アプリを作成」をクリック → 第1段階クリア

〔画像：マイアプリ→アプリを作成→ユースケース選択→作成完了〕

### ② 権限（スコープ）を2つ、アクション状態にする

ダッシュボードに戻り、左メニュー「ユースケース」→「カスタマイズ」。
次の2つを見つけて「追加」を押し、アクション状態にします。

- **threads_basic** … Threads APIを呼ぶなら必ず要る土台の権限。プロフィールや投稿内容を「読む」ための権限（Claude調べ）
- **threads_content_publish** … 投稿を作成・公開する権限。テキスト・画像・動画・カルーセルを本人の代わりに投稿できる（Claude調べ）

〔画像：threads_basic と threads_content_publish をアクション状態に〕

### ③ 自分を「Threadsテスター」として追加する

ダッシュボード→メニュー下の「アプリの役割」→「役割」をクリック（左下に隠れています）。

1. 右上「メンバーを追加」をクリック
2. 役割は「**Threadsテスター**」を選択
3. 追加すると「承認待ち」になる→青文字「ウェブサイトへのアクセス許可」をクリック
4. 飛んだ先で「ウェブサイトのアクセス許可」をクリック
5. 「招待」タブ→作ったアプリ名から招待が来ている→「同意する」
6. 元の画面に戻ると「承認待ち」が消えている＝メンバー追加完了

〔画像：役割追加→承認待ち→同意→完了〕

### ④ アクセストークンを生成する

ダッシュボード→メニュー「公開」→「ThreadsAPIにアクセス」→左メニュー「設定」。
下のほうに追加したThreadsアカウントが出ているので、

1. 対象アカウントの「アクセストークンを生成」をクリック
2. 認証画面で「続行」
3. トークン生成完了→「理解しました」にチェック→トークンをコピー

**注意：PC上で、対象のThreadsアカウントにきちんとログインしておくこと。**
トークン生成時に「いま開いているアカウント」に飛ぶため、別アカウントだとエラーになります。
**生成したトークンは必ずどこかにメモして、なくさないこと。**

〔画像：アクセストークン生成→チェック→コピー〕

### ⑤ トークンを設定ファイル（.env）に直接書く

Claudeはコマンドでの設定手順を教えてくれますが、難しければ**直接ファイルに書くのが早い**です。

1. Claudeで指定したフォルダを開く（やりとりの中で、Claudeが色々なファイルを作っています）
2. 「**env**」というファイルを探す（今回は automation フォルダの中にありました。場所はプロンプト次第で変わります）
3. メモ帳などで開く（Windowsならメモ帳でOK）
4. 「長期アクセストークン」の欄に、さっきのトークンを貼る → 保存

〔画像：automationフォルダ→envファイル→メモ帳でトークンを記入〕

これで、手動の設定は完了です。

### ⑥ Claudeに報告して、実際に投稿を飛ばす

設定できたことをClaudeに伝えると、接続を確認してくれます。
「Threadsアカウントは指定のもので間違いないか」を聞かれるので、間違いなければ進める指示を。

スケジュールも提案してくれますが、ぼくはすぐ確認したかったので「すぐ投稿して」と指示。
全体を一度見たいときは、こう打ちます。

```
--ignore-time
```

即時で1本出すときは、提示された即時コマンドをそのまま。

```
node automation\post-threads.mjs --now <id> --live
```

どの下書きを投稿するか聞かれるので、選ぶだけ。

〔画像：接続確認→アカウント確認→コマンド実行→投稿成功〕

——うん。すごい。**ほんとに投稿されてました。**

## 「直してほしい時」の伝え方（ここで挫折する人が一番多い）

コツは、**「いい感じにして」と言わない**こと。それだとAIも困ります。

```
ここが違います。
いま：〔いまどうなってるか〕
してほしい：〔どうなってほしいか〕
```

- ✕「いい感じにして」→ ○「文字を大きく。色は白っぽく」
- ✕「なんか違う」→ ○「いま：ごちゃごちゃして見える／してほしい：ボタンを2個に減らす」
- ✕「全部直して」→ ○「まず、この1個だけ直してください」

一度に1個ずつ。これがいちばん早いです。

## 詰まった時の、魔法の言葉

エラーっぽい赤い文字が出たら——そのままコピーして、貼って、「これ直して」。
意味を理解する必要はありません。ぼくもSEのくせに、半分くらいはこれで済ませてます。

何をしていいか分からなくなったら：
「いま何がどこまでできてますか？ 次にぼくは何をすればいいですか？」

## 場面別・そのまま使える言い方集

- 見た目を変えたい：「もっとシンプルな見た目に」「スマホで開いても崩れないように」
- 機能を足したい：「〇〇の機能を足して。いまあるものは壊さないで」
- 翌日続きを：「昨日の続きです。いま何ができてる状態か教えて」
- 何をしたか知りたい：「いま何をしたのか、専門用語なしで説明して」
- わからない言葉：「その言葉が分かりません。別の言い方で」
- やり直したい：「さっきの状態に戻して」
- 完成判断：「これで完成にしていい？ 足りないものがあれば教えて」

## 億売り人テクニックの適用マップ
- ヘッドライン9割: タイトルを「自動投稿まで動かした全手順」に拡張（ベネフィット+具体）。各セクションを"得"が分かる小見出しに。
- 読者主語/読まない壁: 冒頭を読者の痛み（コード書けない）起点で開始。
- ベネフィット(FAB): 冒頭「この記事を読み終えると手に入るもの」で先に未来を見せる。
- 信じない壁: 実画面・実コマンド(node automation\post-threads.mjs)・実権限名=1次情報。「検索しても出てこない」で価値を明示。
- 行動しない壁/簡易性: コピペ言い回し集・10案・「一度に1個ずつ」・Q&A(先読み疑問対応)。
- 緊急性/希少性: 「初値・いまが一番安い・実績ついたら値上げ」（煽らず理由で）。
- 物語性/感情: 「うん。すごい。ほんとに投稿されてました」を山場として残す。
