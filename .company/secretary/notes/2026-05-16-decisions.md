## D-026: Bot タスクスケジューラ永続化 完了 (朝の宿題消化)

### 何を解決するか
朝 (D-014 時) の UAC リトライで `register_bot_task.ps1` が **タスク登録は成功したが起動失敗** していた:
- `LastTaskResult: 2147942402` = `0x80070002` (File not found)
- 原因: タスクの Execute が「python」だけ（フルパスじゃない）
- → タスクスケジューラの PATH 解決が効かず File not found

### 根本原因
`register_bot_task.ps1` が `.env` を読む際:
```powershell
Get-Content $envFile | ForEach-Object { ... }
```
PS 5.1 のデフォルトエンコーディングは CP932。
**`.env` は UTF-8 (BOM なし)** で、日本語パス `C:\Users\新日本エネックス岳本\...` を含む。
→ 文字化けで `PYTHON_EXE=` 行のマッチに失敗 → `$pythonExe` が空のまま
→ fallback の `"python"` が Execute に登録された

### 対策

**1. `Get-Content -Encoding UTF8` を明示**
- 日本語パスを正しく読み込めるように

**2. 3 段階フォールバック**
- (a) `.env` の `PYTHON_EXE` を UTF8 で読む
- (b) Get-Command python.exe で探す
- (c) common candidate paths を順次 Test-Path
- (d) すべて失敗ならエラー終了

**3. UAC で再登録 + 起動確認**
- 既存 nohup Bot を停止 → 再登録 → Start-ScheduledTask
- Action.Execute がフルパスになったことを Step 3 で目視確認

### 検証結果
- Execute: `C:\Users\新日本エネックス岳本\AppData\Local\Python\pythoncore-3.14-64\python.exe` ✅
- State: Running ✅
- LastTaskResult: 267009 (TASK_STATE_RUNNING) ✅
- Bot PID: 13132 / Discord Gateway 接続済み ✅

### Why
- nohup 起動依存からの脱却 = **PC 再起動でも Bot が生きてる**
- 落ちたら 1 分後自動再起動 = **24 時間運用に耐える**
- 朝の宿題消化 = Day 1 終了時点との比較で「半自動化が止まらない」が証明

### note 素材
「PowerShell 5.1 で日本語パスを含む .env を読む時の罠」も Day 5 記事の良いネタ。
- BOM なし UTF-8 を CP932 で誤読
- `Get-Content -Encoding UTF8` の明示が必須
- 検証用に `Get-Scheduled​Task | Select-Object Actions` で Execute を目視
