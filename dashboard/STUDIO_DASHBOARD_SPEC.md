## 貼り付け用プロンプト（ここから↓）

このリポジトリの `dashboard/`（Next.js 14 / App Router）に、**バーチャル会社のゲーム風ダッシュボード**を新しいページ `/studio` として追加してほしい。RPGのオフィスみたいに、AIスタッフがデスクに座っていて、上部にKPIカード、右側にスタッフのステータスパネル、左下にアクティビティフィードが出る画面。

データはすべて `.company/` 配下と既存スクリプトの出力から読む（新しい外部APIは増やさない）。専門用語なしで、つまずいたら選択肢で聞いてください。

### 画面構成（3エリア）
1. **上部：KPIカード（横並び5枚）** … 大きな数字＋ラベル＋担当スタッフ名
2. **中央〜左：オフィス図** … スタッフがデスクに座っている俯瞰ビュー（Phase 2でドット絵化。Phase 1は丸アイコン＋名札の簡易表示でよい）
3. **右：STAFFパネル** … 各スタッフのカード（名前・役割・ステータス・直近の成果）
4. **左下：ACTIVITYフィード** … 直近の実行ログ（誰が何をしたか）

### スタッフ（6人）と担当・データ源
| スタッフ | 役割 | KPI | データ源 |
|---|---|---|---|
| サクラ（社長/統括） | 全体統括 | 巡回中/稼働 | 固定表示でOK |
| ソラ（リサーチ） | 競合・トレンド調査 | リサーチ件数・ネタ数 | `.company/research/topics/` の当日 `*-collect.md` 件数 |
| エリカ（発信） | Threads投稿・流入 | 発信インプ・投稿本数 | Threadsメトリクス（下記）＋ `drafts/gaku_ai_life/posted/` の当日件数 |
| ナナ（交流） | リプ/引用でフォロワー関係構築 | 交流件数・新規フォロー | フォロワー数の増分＋返信数（posted の THREADS_METRICS の replies 合計） |
| ユイ（制作） | 無料note・記事制作 | 記事数 | `.company/products/articles/` の記事数 |
| アオイ（営業） | 有料note・収益化 | 売上¥・販売数 | `READY_paid01...` 等の販売実績テーブル（当面は手入力JSONでも可） |

### KPIカード（5枚）の中身
- リサーチ：当日の `research/topics/*-collect.md` 件数（担当ソラ）
- 発信インプ：Threads直近のビュー合計（担当エリカ）
- 交流：返信/コメント合計 or 新規フォロー（担当ナナ）
- フォロワー：現在のフォロワー数（API実数。※画像の「メール登録」はメルマガ未運用なので、ここは「フォロワー」に置き換える）
- 販売：note売上¥（担当アオイ）

### データ取得の具体（既存資産を使う）
- **Threadsメトリクス／フォロワー数**：`scripts/_threads_api.py` の `ThreadsClient` を使う。
  - フォロワー：`GET {API_BASE}/{user_id}/threads_insights?metric=followers_count`
  - ビュー：`metric=views`（期間指定）
  - 認証は `scripts/.env` の既存トークン。**トークンを画面に出さないこと。**
  - 重い場合は、Pythonで集計した結果を `dashboard/` が読めるJSON（例 `.company/reports/studio-data.json`）に書き出す方式でよい（`fetch_all_metrics.py` がHTMLを書くのと同じ要領）。
- **投稿数**：`.company/marketing/drafts/gaku_ai_life/{queued,posted}/` のファイル数。
- **リサーチ件数**：`.company/research/topics/YYYY-MM-DD-*-collect.md` の当日件数。
- **記事数**：`.company/products/articles/*.md`。
- **アクティビティ**：直近のタスク実行ログ／Discord通知ログ／スクリプト出力から「誰が・何を（Read/Edit/WebSearch/投稿）」を時系列で。なければ当面はダミー＋投稿実績で代用。
- **スタッフのステータス（完了/待機/実行中）**：直近に該当データ源が更新されていれば「完了」、なければ「待機」。例：当日のcollectがあればソラ＝完了。

### 段階構築
- **Phase 1（先にこれを動かす）**：KPIカード＋STAFFパネル＋ACTIVITYフィード。オフィス図はデスクの枠＋丸アイコン＋名札の簡易版でOK。データ駆動で正しい数字が出ることを最優先。
- **Phase 2**：オフィス図をドット絵（タイルマップ＋スプライト）にする。素材は軽量なフリースプライト or 単純な図形で開始し、後で差し替え可能に。

### 技術・制約
- 既存 `dashboard/`（Next.js 14・App Router・Tailレイアウト）に `/studio` ルートを追加。既存ページは壊さない。
- ダークテーマ（画像のような濃紺背景＋ネオン文字）。
- 自動更新（30〜60秒ポーリング or 再読込）で最新の数字が出るように。
- 認証情報・APIトークンは絶対に画面/ログに出さない。
- 数字は実データのみ。取れない値は「—」表示（捏造しない）。

まずPhase 1を実装して、ローカルで `npm run dev` → `/studio` で表示確認できる状態にしてください。動いたら見せて。
